# Contributing to the Mobile Robotics Guidebook

This guidebook is maintained by [Robonn](https://robonn.de) — the Robotics Club at Universität Bonn — and is open to contributions from anyone, inside or outside the university.

---

## What We're Building

A human-written, practitioner-focused guide to mobile robotics. The goal is precise, opinionated content that reflects what people actually do in the field — not a surface-level overview generated by an AI. Every page should either teach a concept clearly or point to the best resource for learning it.

---

## How to Contribute

### 1. Fork and clone

```bash
git clone https://github.com/robonn-club/mobile-robotics-guidebook.git
cd mobile-robotics-guidebook
```

### 2. Pick a topic

Check open issues for `help wanted` or `good first contribution` labels, or open a new issue to propose something before starting large additions.

### 3. Write

- Work inside the relevant folder (`courses/`, `resources/`, etc.).
- Each folder has a `README.md` describing its scope — read it before adding content.
- Write in Markdown. Keep explanations direct and technical; avoid filler.
- Include worked examples, code snippets, or diagrams where they add real clarity.
- Cite your sources. If you reference a paper, book, or repository, link it.
- Use `courses/TEMPLATE.md` as a starting point for new course pages.

### 4. Preview locally

```bash
pip install -r requirements.txt
mkdocs serve
# → http://127.0.0.1:8000
```

### 5. Open a pull request

- One topic or fix per PR — keep scope tight.
- Title the PR clearly: `Add EKF localization example` not `updates`.
- Describe what you added and why it belongs here.

---

## Content Standards

| Do | Avoid |
|---|---|
| Explain the *why* behind a method | Restating what a Wikipedia article already says |
| Show real code (Python or C++) | Pseudocode that never runs |
| Reference specific books, papers, repos | Vague "further reading" without links |
| Correct mistakes when you find them | Large reformats without content improvement |

---

## Folder Conventions

```
topic/
├── README.md          # What this folder covers and how to navigate it
├── concept_name.md    # One focused topic per file
└── assets/            # Images, diagrams, or data files for this topic
```

GitHub renders `README.md` automatically — use it as the entry point for every folder.

## Recognition

Everyone who contributes shows up in the **[Contributors](../README.md#contributors)**
image in the README — your avatar, linked to your GitHub profile. It updates
automatically from the commit history, so once your pull request is merged you'll
appear there. You don't need to write a whole chapter — correcting one mistake counts.
